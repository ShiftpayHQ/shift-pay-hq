bf11.8 is a teaching-only geometry/association patch. It removes overlapping parent representations before row construction, prefers tightly bounded complete words over their glyph duplicates, and uses contained words/leaves instead of multi-line parent boxes. Centre-Y and baseline proximity now govern body-row assignment. Excluded hierarchy tokens remain visible in raw diagnostics.

Standalone exact numeric words are captured independently of run reconstruction. Only a proved longer number can invalidate a numeric fragment; a malformed larger run cannot erase an intact monetary word. Word/run representations of the same physical number are deduplicated. Teaching first finds exact normalized occurrences, then associates those occurrences using bounds, physical row, column barriers and nearby baseline labels. One trustworthy unique occurrence may teach a field without a readable label. Repeated values require independent field-specific row evidence; repeated values in neighbouring columns on the same row remain ambiguous. Generic Hours labels cannot resolve repeated OT hours. Conflicting numeric OCR at the same position is rejected.

Per-field diagnostics show target, exact occurrence count, deduplicated candidate/token IDs and text, centres, row, column x, label evidence, final decision and whether the position was actually saved. A selected occurrence is not marked saved if fewer than three anchors pass or storage fails. Profiles still contain positions/dimensions/layout labels only. Full-image normalization, manual field restoration, exact numeric tolerance (0.000001), scanner acceptance, payroll calculations and review-before-save are unchanged.

Existing split monetary, neighbouring-column, missing-digit/decimal and field-preservation tests remain. This is synthetic coverage, not a verified replay of the iPhone OCR stream. bf11.7 replaces teaching's pairwise candidate construction with a shared physical-row model. Body tokens establish median vertical bounds with tolerant overlap/centre checks; small currency and decimal glyphs attach using both baseline and horizontal proximity. Tokens are then sorted left-to-right and partitioned into contiguous numeric runs. Tightly adjacent integer and cents fragments may join around an explicitly captured separator (for example 10 / 60 / . / 0 / 7). Character-width/height-scaled gaps, labels, overlaps and completed decimal cells stop runs. Two standalone numeric cells without separate punctuation evidence remain separate. No decimal or digit is invented, and the teaching equality tolerance remains 0.000001. Normal scan acceptance is unchanged.

The bf11.6 rejection of adjacent integer fragments was a reproducible blocker, and its fixed first-token row bounds could separate decimal punctuation. The actual iPhone stream has not been supplied, so the current implementation does not claim these explain every real-device failure. bf11.6 changes only manual-guided teaching and its DEV diagnostics. Teaching now normalizes currency, Unicode whitespace, grouping commas, explicit comma/middle-dot decimals, limited OCR digit substitutions and trailing colon/semicolon punctuation. Overlapping word/symbol representations are de-duplicated, fragments of a larger number are rejected, and completed decimal cells cannot join another number. Matching requires numeric equality within 0.000001, rather than the previous amount-dependent tolerance. Ambiguous repeats and reuse of one physical candidate by different fields are not saved. Sunday label hints now use the actual field keys.
