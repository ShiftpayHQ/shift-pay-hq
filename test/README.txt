bf11.8 is a teaching-only geometry/association patch. It removes overlapping parent representations before row construction, prefers tightly bounded complete words over their glyph duplicates, and uses contained words/leaves instead of multi-line parent boxes. Centre-Y and baseline proximity now govern body-row assignment. Excluded hierarchy tokens remain visible in raw diagnostics.

Standalone exact numeric words are captured independently of run reconstruction. Only a proved longer number can invalidate a numeric fragment; a malformed larger run cannot erase an intact monetary word. Word/run representations of the same physical number are deduplicated. Teaching first finds exact normalized occurrences, then associates those occurrences using bounds, physical row, column barriers and nearby baseline labels. One trustworthy unique occurrence may teach a field without a readable label. Repeated values require independent field-specific row evidence; repeated values in neighbouring columns on the same row remain ambiguous. Generic Hours labels cannot resolve repeated OT hours. Conflicting numeric OCR at the same position is rejected.

Per-field diagnostics show target, exact occurrence count, deduplicated candidate/token IDs and text, centres, row, column x, label evidence, final decision and whether the position was actually saved. A selected occurrence is not marked saved if fewer than three anchors pass or storage fails. Profiles still contain positions/dimensions/layout labels only. Full-image normalization, manual field restoration, exact numeric tolerance (0.000001), scanner acceptance, payroll calculations and review-before-save are unchanged.

Regression coverage adds PAYE 1060.07 with nested parent/word/glyph boxes, independent printed rows, unique unlabelled amounts, damaged surrounding runs, conflicting OCR, repeated 27.00, and explicit saved status. Existing split monetary, neighbouring-column, missing-digit/decimal and field-preservation tests remain. This is synthetic coverage, not a verified replay of the iPhone OCR stream. A unique amount with no readable label can now teach its position, but later normal scanning still requires its existing label/safety evidence; this patch deliberately does not relax that acceptance path.

bf11.7 replaces teaching's pairwise candidate construction with a shared physical-row model. Body tokens establish median vertical bounds with tolerant overlap/centre checks; small currency and decimal glyphs attach using both baseline and horizontal proximity. Tokens are then sorted left-to-right and partitioned into contiguous numeric runs. Tightly adjacent integer and cents fragments may join around an explicitly captured separator (for example 10 / 60 / . / 0 / 7). Character-width/height-scaled gaps, labels, overlaps and completed decimal cells stop runs. Two standalone numeric cells without separate punctuation evidence remain separate. No decimal or digit is invented, and the teaching equality tolerance remains 0.000001. Normal scan acceptance is unchanged.

The bf11.6 rejection of adjacent integer fragments was a reproducible blocker, and its fixed first-token row bounds could separate decimal punctuation. The actual iPhone stream has not been supplied, so the current implementation does not claim these explain every real-device failure. Per-field raw diagnostics now show label-associated physical rows and immediate neighbours, or the nearest saved-anchor row explicitly marked as uncertain. With neither clue, the region is reported unknown and initial numeric rows are shown. Show all raw rows exposes the rest on demand. Failed PAYE/Gross field panels open automatically. Raw token IDs/text/bounds, excluded duplicate symbols, reconstructed runs, numeric differences and run-boundary reasons are displayed together, making missing/fragmented monetary text inspectable without uploading it.

Tests include synthetic PAYE 1060.07 and Gross 5349.63 split across currency/grouping/decimal/digit tokens at shifted baselines, neighbouring amount columns/rows, missing decimal/digit rejection, raw diagnostic rendering and escaped OCR text. Existing manual-value preservation, profile replacement/retention, ambiguity and scanner tests remain. Only /test changes; no real-device accuracy claim.

bf11.6 changes only manual-guided teaching and its DEV diagnostics. The previous matcher stripped a literal backslash/s rather than whitespace, joined at most two tokens using exact-y ordering and fixed pixel gaps, and used incorrect Sunday hint keys. These defects are reproducible, but the exact cause of the iPhone 0/12 result requires the device's new per-field diagnostics; token count alone does not prove numeric readability.

Teaching now normalizes currency, Unicode whitespace, grouping commas, explicit comma/middle-dot decimals, limited OCR digit substitutions and trailing colon/semicolon punctuation. Close same-line token sequences (up to eight parts) can reconstruct split numbers. Explicit separators are required when joining digits; missing decimal points and digits are never inferred. Overlapping word/symbol representations are de-duplicated, fragments of a larger number are rejected, and completed decimal cells cannot join another number. Matching requires numeric equality within 0.000001, rather than the previous amount-dependent tolerance. Ambiguous repeats and reuse of one physical candidate by different fields are not saved. Sunday label hints now use the actual field keys.

Every teaching field reports its manual value, normalized target, selected candidate or rejection, and candidate text/value, coordinates, numeric difference and normalization changes. The twelve closest numeric representations are shown first; the Show all candidates button renders every considered representation for that field on demand. Diagnostics are escaped, held only in page memory, cleared for a new scan, and excluded from the saved profile. Manual fields are preserved. At least three safely located anchors remain required; a failed teaching attempt leaves the old profile untouched. Success replaces it at the existing key with v3 full-image coordinates, image dimensions and OCR bounds, never historical values.

Regression tests include a synthetic 1,411-token scan reconstructing all twelve fields, repeated amounts with distinct row labels, ambiguity, whitespace/punctuation/substitutions, split decimals with baseline jitter, fragments, cross-row/column rejection and unchanged manual values. Normal scan matching, payroll rules, confirmation-before-save and the root app are unchanged. Re-test locally on iPhone; synthetic results are not a real-device accuracy claim.
